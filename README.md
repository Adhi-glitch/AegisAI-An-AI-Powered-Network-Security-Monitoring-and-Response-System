## What this project does today

This project builds a network intrusion detection and response baseline for CICIDS-style traffic:

- loads and normalizes CICIDS CSV data
- creates stratified training/validation/test samples
- trains a detection model and an IsolationForest anomaly detector
- explains the prediction using feature importance
- stores alert, detection, and action records in SQLite
- exposes the dashboard and stats via FastAPI
- supports replay of detections for offline testing

This is a complete milestone pipeline, not a placeholder.

## Implemented security extensions

The current backend includes an offline-first response policy evaluator at
`/api/v1/response/policy/preview`, authenticated Copilot retrieval at
`/api/v1/copilot/query`, and incident correlation/report endpoints at
`/api/v1/incidents/correlate` and `/api/v1/incidents/report`. The response
engine remains dry-run by default. Admin-only actions and rollback are protected
by JWT role checks; the API explicitly rejects `auto-live` execution because
live firewall enforcement is disabled.

The Copilot currently uses deterministic local lexical retrieval and seeded
MITRE/AegisAI documents. It is deliberately honest about weak retrieval and
does not claim to be an embedding or external-LLM index. Persistent response
approvals, audit records, incidents, feedback, assets, saved searches, and
watchlists are supported by the SQLite schema.

### Frontend and offline demo

```powershell
cd frontend
npm run build
npm run dev
cd ..
python scripts\demo_scenario.py
```

The demo represents a five-minute Port Scan -> Brute Force -> Botnet sequence
without sending packets or changing the host firewall. The React source lives
under `frontend/src`; the built bundle is generated by Vite.

Response approvals and durable audit records are available through
`/api/v1/response/execute`, `/api/v1/response/approvals`,
`/api/v1/response/approvals/{id}/decision`, and `/api/v1/response/audit`.
Admins can ingest local Copilot documents through
`POST /api/v1/copilot/documents`; notification hooks remain disabled until
their environment variables are configured.

### Admin and viewer capabilities

Administrators can control capture, ingest alerts, replay demos, create
policies, run dry-run response actions, approve/reject queued requests, manage assets and threat feeds,
run simulations, ingest Copilot documents, manage incidents, and use the
allowlisted Admin Tools console. Viewers can inspect detections, incidents,
reports, intelligence, posture, assets, and model health; ask Copilot
questions; search/save alerts; create watchlists; and request approval-required
actions. Viewers cannot execute actions or change system configuration.

The complete route-level matrix is in [docs/FEATURE_STATUS.md](docs/FEATURE_STATUS.md).

## Quickstart

Run everything in one PowerShell session:

```powershell
cd "Your Project Dir"
Copy-Item .env.example .env
# Edit .env and replace all placeholder values with unique secrets.
.\.venv\Scripts\Activate.ps1
npm --prefix frontend ci
npm --prefix frontend run build
python scripts\sample_splits.py --train-size 300000
python -m ml.training.train
python -m ml.evaluation.evaluate
python database\init_db.py
uvicorn backend.app:app --reload --port 8000
```

Open http://127.0.0.1:8000/ for the public AegisAI homepage. `/signin` opens the operator sign-in form, and `/dashboard` opens the React/Vite console after authentication. `/legacy` temporarily retains the older Jinja live-capture dashboard. The backend requires a 32-byte signing key and distinct admin/viewer passwords of 12-72 bytes; the example values must be replaced before startup.

### Self-hosted Docker Compose

The self-hosted Compose stack runs the existing FastAPI application and PostgreSQL locally; it does not provision paid cloud services. Docker Engine/Compose, disk, network access for the initial image downloads, and machine power are still required. The backend container is intentionally unprivileged and does not capture host traffic directly; live capture requires the separate host-agent integration.

```powershell
Copy-Item .env.example .env
# Edit .env and replace all placeholder passwords and the signing key.
npm --prefix frontend run build
docker compose up --build
```

The console is available at `http://127.0.0.1:8000/`. The PostgreSQL database is private to the Compose network and stored in a named volume. Do not commit `.env`.

Optional: replay detections into the local DB/API:

```powershell
python scripts\replay_detections.py --limit 30 --post-api
```

## GPU support

The training script automatically prefers XGBoost on CUDA when a supported NVIDIA GPU is detected.
If CUDA is unavailable, it falls back to CPU-based training automatically.

```powershell
python -m ml.training.train --engine auto
```

You can force a specific engine:

```powershell
python -m ml.training.train --engine xgboost
python -m ml.training.train --engine random_forest
```
